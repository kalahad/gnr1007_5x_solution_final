Zone 01 · Work Order Bay

แผงงานช่าง: ชิ้นส่วนของฟังก์ชันที่ต้องอ่านให้ครบ

ฟังก์ชันคือ ช่างในพิทที่มีหน้าที่เฉพาะตัว เรียกเมื่อไรก็มาทำงานให้ ใบสั่งงานหนึ่งใบบอกครบสามอย่างเสมอ คือ คืนอะไรกลับ (return type) ชื่อช่าง (function name) และ ต้องส่งอะไรให้ (parameter)

int add(int a, int b) { int result = a + b; return result; } int main(void) { int sum = add(3, 5); printf("%d", sum); return 0; }
ชิ้นส่วนในโค้ดคือในพิทเลนคือ
Return typeint ตัวหน้าสุดของบรรทัดหัวฟังก์ชันชนิดของชิ้นงานที่ช่างจะส่งกลับ
Parameterint a, int b ในวงเล็บของนิยามอะไหล่ที่เราส่งให้ช่าง
Argument3 และ 5 ตอนเรียกใช้ของจริงที่ยื่นให้ตอนสั่งงาน
returnส่งค่ากลับแล้ว จบฟังก์ชันทันทีช่างส่งงานเสร็จแล้วปิดไฟกลับบ้าน
voidไม่มีของส่งกลับ ทำงานอย่างเดียวช่างที่มาเช็ดกระจกให้ ไม่มีชิ้นงานส่งคืน

จุดหลอกสิ่งที่มักตอบผิดข้อเท็จจริง
ลำดับการทำงานคิดว่าฟังก์ชันที่เขียนไว้บนสุดทำงานก่อนโปรแกรมเริ่มที่ main เสมอ ฟังก์ชันอื่นทำงานเมื่อถูกเรียกเท่านั้น
Argument จับคู่ Parameterคิดว่าจับคู่ตามชื่อตัวแปรจับคู่ ตามตำแหน่ง เท่านั้น sub(10, 4) กับ sub(4, 10) จึงให้คนละคำตอบ
โค้ดหลัง returnคิดว่ายังทำงานต่อเจอ return เมื่อไร ออกจากฟังก์ชันทันที แม้อยู่กลางลูปก็เด้งออกทั้งฟังก์ชัน

ทักษะที่จะได้: Pass by Value

รู้ว่าการส่งค่าให้ฟังก์ชันคือการ ส่งสำเนาแบบแปลน ไม่ใช่ตัวรถจริง ช่างขีดเขียนบนสำเนาอย่างไร ตัวแปรของผู้เรียกก็ไม่เปลี่ยน

Zone 02 · Blueprint Copier

ห้องถ่ายเอกสารแบบแปลน: ส่งสำเนา ไม่ใช่ส่งตัวจริง

เมื่อเราเขียน change(a) ภาษา C จะ ถ่ายสำเนาค่าของ a ใส่กล่องใหม่ ให้ฟังก์ชันใช้ กล่องใหม่นี้อยู่คนละที่กับกล่องของ main ช่างจะขีดเขียนบนสำเนาอย่างไร กล่องเดิมก็ไม่ขยับ นี่คือ จุดหลอกอันดับหนึ่ง ของบทฟังก์ชัน

void change(int x) { x = 99; printf("%d ", x); } int main(void) { int x = 5; change(x); printf("%d", x); return 0; }
สิ่งที่นักศึกษาคิดสิ่งที่คอมพิวเตอร์ทำจริง
ส่ง x เข้าไปแล้วแก้เป็น 99 ตัว x ใน main ก็ต้องเป็น 99ฟังก์ชันได้ สำเนา ผลลัพธ์จึงเป็น 99 5 กล่องของ main ไม่ถูกแตะเลย
ถ้าตั้งชื่อพารามิเตอร์ให้ตรงกับตัวแปรเดิม จะเป็นตัวเดียวกันชื่อซ้ำกันไม่เกี่ยวข้องกัน คนละกล่อง คนละที่อยู่ในหน่วยความจำ
เขียน swap(p, q) แล้วค่าจะสลับกันสลับได้เฉพาะสำเนาข้างใน ออกจากฟังก์ชันมาค่าเดิมทั้งคู่
เรียกฟังก์ชันแล้วค่าจะเปลี่ยนเองต้อง รับค่ากลับมาเก็บ เช่น v = dbl(v); จึงจะเปลี่ยนจริง

ทักษะที่จะได้: Local vs Global

รู้ว่าเครื่องมือในกล่องส่วนตัวของช่างแต่ละคนไม่ปนกัน และเมื่อชื่อซ้ำกับเครื่องมือกลางที่แขวนไว้ในพิท ช่างหยิบของตัวเองก่อนเสมอ

Zone 03 · Toolbox Corner

กล่องเครื่องมือส่วนตัว: ใกล้ตัวชนะไกลตัวเสมอ

ตัวแปรที่ประกาศ นอกทุกฟังก์ชัน คือเครื่องมือกลางที่แขวนไว้ในพิท ใครก็หยิบได้ (Global) ส่วนตัวแปรที่ประกาศ ในฟังก์ชันหรือในบล็อกปีกกา คือเครื่องมือในกล่องส่วนตัวของช่างคนนั้น (Local) เมื่อชื่อซ้ำกัน ช่างจะหยิบของในกล่องตัวเองก่อนเสมอ ของกลางจึงถูก บัง ไว้ชั่วคราว

int n = 100; void show(void) { printf("%d ", n); } int main(void) { int n = 5; printf("%d ", n); show(); n++; printf("%d", n); return 0; }
บรรทัดใช้ตัวไหนเพราะอะไร
printf ตัวแรกใน mainlocal n = 5main มี n ของตัวเอง จึงบัง global ไว้
printf ใน showglobal n = 100show ไม่ได้ประกาศ n ของตัวเอง จึงมองเห็นแต่ของกลาง
n++ ใน mainlocal nแตะเฉพาะกล่องส่วนตัว ค่า global ยังเป็น 100 เท่าเดิม
printf ตัวสุดท้ายlocal n = 6ผลลัพธ์รวมของโปรแกรมนี้จึงเป็น 5 100 6

จุดหลอกข้อสอบ กว. ของโซนนี้

จุดหลอกข้อเท็จจริง
คิดว่า local ที่ชื่อซ้ำจะไปแก้ค่า global ด้วยคนละกล่องกันสนิท แก้ local แล้ว global ไม่ขยับ
คิดว่า local อยู่ต่อหลังฟังก์ชันจบตัวแปร local เกิดใหม่ทุกครั้งที่เรียก และหายไปเมื่อฟังก์ชันจบ
คิดว่าเรียกใช้ local ของฟังก์ชันอื่นได้เรียกไม่ได้เลย ถ้าเขียนจะ คอมไพล์ไม่ผ่าน ทันที
ลืมว่าพารามิเตอร์ก็เป็น local ชนิดหนึ่งชื่อพารามิเตอร์บัง global ที่ชื่อเดียวกันได้เหมือนกัน
